# Decisions and extras

The README carries a ten-row summary. This page is the longer index: one row per headline decision with the alternative I turned down, and then every item I built beyond the brief with its justification, cost and status. The reasoning is in the Why column; where a row has an entry on the [decisions page](https://clinic.ericgitangu.com/decisions), it is linked. Who decided what is in [`docs/engineering/ai-usage-facts.md`](ai-usage-facts.md).

## Headline decisions

| Decision | Rejected alternative | Why | What it costs | Decisions page |
|---|---|---|---|---|
| A partial unique index on `(doctor_id, starts_at) WHERE status = 'booked'` decides double booking | `EXCLUDE USING gist`, SERIALIZABLE with retries, advisory locks, check-then-insert | It is the smallest mechanism the engine enforces itself, so it holds across instances with no coordination | Correct only for fixed, aligned 30-minute slots; variable lengths need the `EXCLUDE` form | [double booking](https://clinic.ericgitangu.com/decisions#double-booking) |
| Slots are computed from working hours | A materialized `slots` table, an RRULE engine | The brief's working hours stay the only source of truth, so nothing drifts | No slot row to lock, so uniqueness lives on the appointment | [double booking](https://clinic.ericgitangu.com/decisions#double-booking) |
| FastAPI is the single system of record | Django REST Framework; FastAPI plus a Go service in the write path | One runtime, typed end to end, and the OpenAPI document generates the client | Python cold starts; no latency target was measured | [one API](https://clinic.ericgitangu.com/decisions#one-api) |
| UTC `timestamptz`, the clinic zone as data, an injected clock | The zone in environment config; naive local timestamps | A second clinic needs no code change, and tests pin time | An extra join to read the zone | [time model](https://clinic.ericgitangu.com/decisions#time) |
| RFC 9457 problem details with a closed code catalogue | FastAPI's default `{"detail": ...}`; a custom envelope | Clients need a stable machine-readable `code`; the brief asks for correct status codes | A typed exception hierarchy to maintain, checked by a test against `contracts/api-errors.md` | [REST contract](https://clinic.ericgitangu.com/decisions#rest-and-errors) |
| REST with OpenAPI 3.1, and a client generated from the contract | tRPC, GraphQL, gRPC | The brief says REST; tRPC needs a TypeScript server; GraphQL hides status codes | Type safety comes from codegen and a CI drift gate; the generator is 0.x and pinned | [REST contract](https://clinic.ericgitangu.com/decisions#rest-and-errors) |
| Reschedule is one in-place `UPDATE` under `SELECT ... FOR UPDATE` | Cancel and reinsert; an unlocked conditional update | The appointment id stays stable and the old slot frees atomically | A swap can end with both requests rejected after one retry | No entry |
| An idempotency key stored on the appointment row, with a request fingerprint | No idempotency; a separate table of stored responses | A lost response must not tell the real booker they lost the slot, and the replay must not need a second store | A key is bound to one doctor and time; reuse with a different body is a 422 | No entry |
| Cloud Run is IAM-only behind a Vercel proxy, in `us-east4` beside Neon in `aws-us-east-1` | Cloud Run in `africa-south1` or `europe-west3` with Neon in Frankfurt; Cloud SQL | I set a $0 rule, and egress to Kenya is billed from byte 0 outside North America; four to six database round trips per booking need the API beside the database | A longer hop for Kenyan users (an estimate, not measured); about $0.34 a month on the shared billing account | [hosting and cost](https://clinic.ericgitangu.com/decisions#hosting-and-cost) |
| Two database roles: an owner for migrations and an app role with no DDL rights | One role for everything | A compromised service cannot change the schema | Two secrets and two service accounts | No entry |
| CircleCI, keyless OIDC to workload identity federation, promote by tag after a smoke test, roll back automatically | Cloud Build; a long-lived service-account key | No long-lived GCP credential exists, and only a smoke-tested revision gets traffic | `VERCEL_TOKEN` is long-lived; a main pipeline takes about 10 to 12 minutes (an estimate) | [README section 9](../../README.md#9-deployment--cicd) |
| Real Postgres in every test, a race harness that must fail without the index | Mocked repositories on SQLite | A mock cannot show a unique violation under contention | Slower suites; a compose database in CI | No entry |
| Public API stays unauthenticated; patients and staff sign in with Google in the web apps | Mandatory auth on the API; optional bearer auth | The brief is silent on authentication; the endpoints and Swagger "Try it out" work without it | An IDOR on the public API, disclosed in the README | [the thin web layer decision](https://clinic.ericgitangu.com/decisions#thin-web-layer) |
| Better Auth with stateless session cookies; roles looked up on every request | Auth.js v5 beta; roles in the cookie; an email list in an environment variable | Maintained, database-free sessions, and a revoke takes effect on the next request | One table lookup per request; cookies cannot be revoked early | [thin web layer](https://clinic.ericgitangu.com/decisions#thin-web-layer) |
| Server actions call the API, with one reCAPTCHA check per action | Browser calls through the proxy | No browser code holds a credential, and the human check runs on the server | The public `/api` proxy is not covered by the check | No entry |
| Two apps in one pnpm workspace | One app with an `/admin` route group; two repositories | Separate auth surfaces and deploys without publishing shared packages | Two Vercel projects to keep in step | No entry |
| Plain JSON logs with a `request_id` and no PII | OpenTelemetry to Cloud Trace; Sentry | Smallest thing that lets a problem body lead to a log line, within the free tier | No traces, no alerting beyond the cost checks | No entry |
