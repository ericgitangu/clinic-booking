## How it came to exist

The first version of this budget was created by Terraform (`google_billing_budget.run_spend_cap_3usd`,
id `c193126c-b3ca-4076-98b6-e451c5c531ed`) and was alerts-only; the console showed
"Spend cap status: Not applicable". The console refused to create a capped budget while it existed
("potential duplicate"): a spend cap allows one budget per project and service, and an existing
budget cannot be converted. The Terraform budget was deleted and the console budget was created
under the same name. The resource was then removed from `infra/billing/budget.tf` so a later apply
cannot recreate the alerts-only one.

`clinic-alerts-1usd` (alerts-only, $1, project scope) stays in Terraform.

## What this does and does not prove

- The cap is a backstop. The $0 mechanism is the free-tier arithmetic and the ticket budget; nothing
  here makes the project free by itself.
- Observed in the console by the engineer on 2026-10-18. It is a recorded observation, not an API
  read, and nothing re-checks the console itself: if the budget is edited there, this file is stale.

## Terraform state clean-up (run after the PR that removes the resource is merged)

The state in `gs://clinic-tfstate-sil-clinic-booking` (prefix `clinic/billing`) still holds the
deleted alerts-only budget `c193126c-b3ca-4076-98b6-e451c5c531ed` as
`google_billing_budget.run_spend_cap_3usd`, at state serial 2. Until it is removed, `plan` would
try to recreate it. Run as the billing identity (not by CI, not by the PR author):

```bash
export GOOGLE_OAUTH_ACCESS_TOKEN=$(gcloud auth print-access-token --account "$BILLING_GCLOUD_ACCOUNT")
terraform -chdir=infra/billing init -backend-config="bucket=clinic-tfstate-sil-clinic-booking"
terraform -chdir=infra/billing state rm google_billing_budget.run_spend_cap_3usd
terraform -chdir=infra/billing plan    # expect: no changes for clinic-alerts-1usd, nothing to create
```

`state rm` only forgets the resource; it does not call the Billing API, so the console budget
`bfd734ab-ef98-414a-8bb1-b6442c1dec94` is untouched. Expected serial after `state rm`: 3. If `plan`
shows any change to `clinic-alerts-1usd`, stop and compare it with `infra/billing/budget.tf`.
